# 教學整理流程

把一篇改筆教學（FB 貼文、文字、照片）整理成統一格式，放上 HackMD，再上架到網站。格式規則見 [SPEC.md](../SPEC.md)。

## 流程總覽

```
你貼教學給 Claude
  → Claude 整理成統一格式，在 HackMD 團隊建立新筆記（草稿：不加進總目錄）
  → 你在 HackMD 確認
  → 你說「上傳」
  → Claude 把連結加進總目錄、觸發同步
  → 約 1 分鐘後出現在網站
```

網站只抓「總目錄」裡有連結的筆記，所以還沒加進總目錄的筆記就是草稿，不會出現在網站上。

## 1. 收集內容

可以給 Claude 的東西（擇一或混用）：

- **FB 貼文連結**：Claude 用你的 Chrome 讀
- **直接貼文字**：複製貼文和留言
- **照片**：拖進對話，或放在資料夾告訴 Claude 路徑

### 從 FB 貼文整理時

1. 留言排序切成「所有留言」，展開所有「查看更多」與回覆。
2. 步驟通常在作者自己的留言裡，**順序是亂的**。依作者的編號（一、二、1-1、1-2…）重新排列，不要照留言時間。
3. 各部分對應：

| FB 上的內容 | 放到筆記的哪裡 |
|---|---|
| 貼文本文、完結留言裡的數據（長度、重量、離心力） | 相關數據 |
| 材料列表留言 | 所需材料 |
| 「前言」、材料注意事項 | 材料注意事項（放在所需材料之後） |
| 作者按編號發的步驟留言 | 教學（步驟一、步驟二…） |
| 其他人的實用提醒 | 補充，結尾註明「感謝 某某 提醒」 |
| 作者的心得、後記 | 作者的話（**直接複製原文，不改寫**） |
| 閒聊、單純稱讚 | 不收 |

### 原文規則

- 「作者的話」一律**直接複製作者貼文的原文**，不改寫、不改人稱、不修標點，只拿掉已經放進「相關數據」的筆名、長度、重量等行。
- 步驟說明可以整理成統一格式，但不能改變作者的意思。

## 2. 照片

1. FB 留言裡只有縮圖。要從照片檢視器取原圖，並用**檔名前綴**比對縮圖與原圖，避免抓錯。
2. 封面用成品照；材料合照放在「所需材料」下面；完成照可以放在「作者的話」。
3. 所有照片上傳到 HackMD 的圖床（`hackmd.io/_uploads/...`），**不外連 FB 或其他網站**，以免日後失效。
4. 「圖片所有者」寫原作者。

## 3. 格式（重點，完整規則見 SPEC.md）

- 檔頭寫 `title:`（筆名）和 `tags:`（分類, 改筆教學, tutorials）
- 長度一律 cm、重量一律 g，**不寫「約」**，範圍用 `21–22 cm`
- 材料：`材料名（使用部位）：數量`，數量用阿拉伯數字，括號冒號用全形
- 步驟標題：`#### 步驟一　小標題`（小標題選填）
- 每一步：**先寫動作說明，照片放在說明下面**
- 備註一律 `註：`
- 缺資料寫「待補充」
- 段落順序固定：相關數據 → 所需材料 →（材料注意事項）→ 教學 → 補充 → 作者的話 → 編者心得 → 影片
- 最後一行 `> 圖片所有者：名字`

## 4. 建立 HackMD 草稿

1. 在 HackMD 團隊 TWPS改筆百科 按「建立團隊筆記」。
2. 貼上整理好的內容，照片用貼上的方式上傳。
3. 到筆記設定 → 一般設定，把「標題」設成筆名（HackMD 不會自動從內文更新標題）。
4. **先不要加進總目錄**，把筆記連結給你確認。

## 5. 上架到網站

你確認沒問題後：

1. 在「總目錄」對應分類（雙頭／G3／VP／Mx…）最後面加一行 `[筆名](/筆記ID)`，並把「最後更新日期」改成今天。
2. 到 GitHub repo 的 **Actions → Sync from HackMD → Run workflow** 手動同步。
3. 約 1 分鐘後網站更新。新教學會出現在首頁「最近更新」第一張。

## 已知的坑

- HackMD 筆記標題只能從「筆記設定」改，改內文第一行不會更新卡片上的標題。
- 標籤要寫在檔頭的 `tags:`，只寫底部 `###### tags:` 有時不會被 HackMD 歸類。
- Mac 的 Chrome 預設 Google 帳號不是 tacotwps；用 Google 服務時要切到 `/u/1/`。
